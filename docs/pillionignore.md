# `.pillionignore` and what Pillion indexes

Pillion indexes the files of your repository so chat, `@`-mentions and search can find the right few thousand tokens. This page
says which files it leaves out, in what order the rules apply, and how to leave out more, or take something back in, with a
`.pillionignore` file. The rules are implemented in `src/Pillion.Indexing` (work item 2.3; see its README for the code-level
view). The window that shows the result is [the Index window](index-window.md).

## The file

Put a file named `.pillionignore` at the **root of the repository** (the git top-level folder, or the opened folder when there
is no git repository). Only that one file is read; a `.pillionignore` in a subfolder is ignored. The Index window's **Excluded
files** tab has an **Open .pillionignore** button that opens it, creating it with a one-line comment if it does not exist.

The syntax is the one of `.gitignore`:

| Line | Meaning |
| --- | --- |
| blank, or starting with `#` | Skipped |
| `build/` | A trailing `/` limits the rule to directories |
| `/generated` or `src/legacy` | A leading or inner `/` anchors the rule to the root |
| `*.snap` | A rule without a `/` matches at any depth |
| `*`, `?` | Wildcards; they never match across a `/` |
| `[a-z]`, `[!a-z]`, `[[:digit:]]` | Character classes, with ranges, negation and POSIX names |
| `**/Migrations/**` | `**` counts as a whole path segment: any number of directories |
| `\#file`, `\!file` | A backslash escapes the next character |
| `!keep.json` | A leading `!` negates: the path is explicitly **not** ignored |

The last matching rule wins. Names match without regard to case, as on Windows. A directory that is excluded is not entered, so
nothing inside it is looked at. The matcher is Pillion's own implementation of git's `gitwildmatch` subset, compiled to string
comparisons or non-backtracking regular expressions, so a pattern from a cloned repository cannot slow indexing down. Not
supported: `.git/info/exclude`, the global excludes file, and `core.ignorecase=false`.

Pillion reads the file again when it changes (the file watcher forgets its cached rules and sweeps the repository), so an edit
takes effect without restarting anything. Excluded files already in the index are removed by that sweep.

## What is left out, in order

For each file Pillion applies the rules below in this order; the first that fires is the reason the Index window shows. A
directory is excluded as a whole by rules 1, 3, 4, 5 and 6, or as a **nested repository** when it holds its own `.git` (that
repository is indexed under its own root).

| # | Rule | Reason shown |
| --- | --- | --- |
| 1 | A symbolic link or junction: never followed, files and directories alike | Link or reparse point |
| 2 | A secret-bearing name (below) | Secret-bearing file |
| 3 | `.gitignore` at every level (a deeper file overrides a shallower one; `!` negation, anchoring, directory-only rules and `**` as in git) | Ignored by .gitignore |
| 4 | The root `.pillionignore`, which comes after `.gitignore`: its rules ignore, and its `!` rules re-include what `.gitignore` ignored | Ignored by .pillionignore |
| 5 | A built-in name (below) | Built-in exclusion |
| 6 | The `indexing.exclude` setting, and a repository policy's `exclude`, same syntax, relative to the root | Matches indexing.exclude |
| 7 | Generated names: `*.g.cs`, `*.g.i.cs`, `*.designer.cs`, `*.generated.cs` (and the `.vb` forms) | Generated file |
| 8 | Minified `*.min.js`, `*.min.css` | Minified file |
| 9 | Lock files: `package-lock.json`, `npm-shrinkwrap.json`, `yarn.lock`, `pnpm-lock.yaml`, `packages.lock.json`, `composer.lock`, `Cargo.lock`, `poetry.lock`, `Pipfile.lock`, `Gemfile.lock`, `go.sum`, `bun.lockb` | Lock file |
| 10 | Larger than 1 MB | Too large |
| 11 | An auto-generated header in the first 2 KB: `<auto-generated`, `<autogenerated`, `@generated`, the protocol buffer notice, or Go's `Code generated ... DO NOT EDIT` | Generated header |
| 12 | A NUL byte in the first 8 KB (a UTF-16 file with a byte order mark is text) | Binary file |
| 13 | A file that cannot be opened (locked, access denied, vanished) | Unreadable |

Rules 1 to 10 use only the name and the directory entry: an excluded file is never opened. A locked file keeps its stored row
and is looked at again next time. Files that pass every rule are indexed if their extension maps to a language Pillion knows
(`csharp`, `vb`, `razor`, `typescript`, `javascript`, `python`, `c`, `cpp`, `go`, `rust`, `java`, `sql`, `html`, `css`); any other
text file is indexed as `other` and chunked in 60-line windows.

### Built-in names

At any depth, files and folders named `bin`, `obj`, `node_modules`, `.git` and `.vs` are excluded.

**`packages` is narrower.** A folder named `packages` is excluded only when it sits **at the repository root** and looks like a
NuGet packages folder: it holds a `repositories.config`, or a `*.nupkg` file one or two levels down. Any other `packages` folder
(for example `src/packages` in a JavaScript monorepo, or `packages/` holding your own projects) is source and is indexed. A file
called `packages` is never a built-in.

### Taking a built-in back in

A `!` rule in the **root `.pillionignore`** opts back in to a built-in name, at the depth you write it:

```
# A monorepo whose packages\ folder is source, and a checked-in tools\bin
!packages/
!tools/bin/
# Re-include a folder name at any depth
!obj/
```

- `!packages/` re-includes the root `packages` folder even if it looks like a NuGet folder.
- A rule without a `/` in the middle matches at any depth; `!obj/` re-includes every `obj` folder, while `!tools/bin/` re-includes
  only that one.
- `.git` can never be opted back in to.
- A negation in `.pillionignore` also re-includes what `.gitignore` ignored. With `generated/` in `.gitignore`, `!generated/` in
  `.pillionignore` indexes it; `drop.gen.json` stays excluded by `.gitignore` unless you also write `!drop.gen.json`.
- A negation **cannot** undo `indexing.exclude` (or a policy's `exclude`), cannot undo the secret list, and a `!` rule written
  *inside* `indexing.exclude` does not re-include a built-in either.

## Secret-bearing files

The rule for secrets comes **first** among the content rules (right after links) on purpose: a `.env` that `.gitignore` also
lists is still reported as secret-bearing, so the Index window shows it. A file whose name matches any of these is never opened,
never hashed, never stored, whatever `.gitignore` or `.pillionignore` says:

`.env`, `.env.*`, `*.pfx`, `*.pem`, `*.key`, `*.p12`, `secrets.json`, `appsettings.*.json`, `*.publishsettings`, `id_rsa`,
`id_dsa`, `id_ecdsa`, `id_ed25519`, `*.ppk`, `*.jks`, `*.keystore`, `.netrc`, `.pgpass`.

What this means in practice:

- They are listed first on the Index window's **Excluded files** tab, with a shield, and counted in the header.
- Nothing in them is searchable, and retrieval never returns their text.
- `@file` on one asks first ("It looks like a secret file ... Approve it to pin the file"). Once you approve it, it is pinned for
  that conversation with a lock, and it is **never sent to a cloud model**. See [mentions.md](mentions.md).
- `indexing.exclude` and `.pillionignore` cannot bring them in.

`appsettings.*.json` is on the list whole, so `appsettings.Development.json` is excluded even if it holds no secret; `appsettings.json`
itself is indexed. A key written into an ordinary source file is not detected by name: it is stored in the encrypted index
(see [design document](design-document.md) section 12, Phase 2 note) and redacted by the scanner if the text goes to a cloud model.

## Examples

```
# Pillion does not index paths listed here. The syntax is the one of .gitignore.

# Large generated sample data and snapshots
testdata/
*.snap

# A vendored copy we do not want in search results
/third_party/

# The legacy folder is excluded, except its README
legacy/*
!legacy/README.md

# gitignore hides generated code; we want it searchable
!src/generated/

# A packages\ folder that holds our own projects
!packages/
```

Note `legacy/*` rather than `legacy/`: git's rule applies here too, so a file cannot be re-included once its parent directory is
excluded as a whole. Excluding the folder's contents with `legacy/*` leaves the folder open for the `!` rule.

## Settings that work alongside

| Setting | Effect |
| --- | --- |
| `indexing.exclude` (Options > Pillion Programmer > Indexing) | User-wide patterns, `.gitignore` syntax, relative to each root. Cannot be re-included from `.pillionignore` |
| `exclude` in `.pillion/policy.json` | A repository's own patterns, applied for everyone who opens it; a policy can only add exclusions |
| `mentions.docsFolders` | Extra documentation folders `@docs` reads (they are not indexed by this mechanism) |

See [index-window.md](index-window.md) for the options page and the Excluded files tab.
